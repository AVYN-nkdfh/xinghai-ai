# 星海工作室机位预约｜生产契约 v1.2

更新时间：2026-07-22

## 页面与任务

- 家长端 `/booking`：选择未来 7 天中的一个日期，可同时选择一个或多个时段，再选择一台在所有所选时段均可用的机器并一次提交。
- 管理端 `/booking#admin`：密码登录后按日期和时段查看预约；可维护当前时段、批量维护当天全部时段，或将机器设为长期维护直到恢复。

## 核心状态

- 机器：可选、选中、部分时段占用、已预约、临时维护、长期维护、时段关闭。
- 请求：加载中、失败、提交中、成功、并发占位冲突。
- 管理端：未登录、登录失败、空预约、已预约、单时段维护、全天维护、长期维护、时段关闭。

## 多时段规则

- 仅支持同一天内多选上午、下午、晚间，不跨日期批量预约。
- 家长端提供“全选当天”；至少保留一个时段。
- 座位图聚合所选时段：只有全部所选时段均可用的机器才可点击。
- 一次提交为一个预约组；各时段占位必须在同一事务内全部成功或全部失败。
- 成功凭证列出全部时段；后台取消预约组时释放该组全部时段。

## 维护规则

- 当前时段维护：只影响所选日期和当前时段。
- 当天全部时段维护：一次影响所选日期的三个时段；任一时段已有预约时整次操作失败。
- 长期维护：影响该机器所有日期和时段，直到管理员恢复；存在未来有效预约时不能开启。
- 长期维护恢复后，原有单日临时维护记录仍按原规则生效。

## 性能规则

- 某个日期首次加载后，三个时段的数据一次返回并缓存。
- 上午、下午、晚间之间切换或多选时只更新本地状态，不发起新的网络请求。
- 已有缓存时后台刷新不得清空座位图或阻塞点击。

## 生产资源规则

- 正式域名启用 clean URL，`/booking/` 会规范为 `/booking`。
- 构建必须同时生成 `dist/booking.html`，由 clean URL 稳定映射 `/booking`；目录内的 `booking/index.html` 仅作为源结构保留。
- 页面脚本必须使用 `/booking/booking.js` 的站点绝对路径，不能依赖 `./booking.js`。
- 同域接口固定为 `/api/booking/*` 与 `/api/admin/*`。

## 接受条件

- `/booking/` 跳转后的最终 `/booking` 返回 200，页面脚本成功加载并渲染 7 个日期、3 个时段、6 台机器。
- 两排机器为 1/2/3 与 4/5/6 面对面。
- 连续点击三个时段时座位图立即更新，不出现“正在读取机位”。
- 两个或三个时段可一次预约同一机器，并在后台作为一个预约组读取和取消。
- 当前时段、当天全部时段、长期维护均可设置与恢复。
- 家长写入、管理员读取和取消均落到云端 PostgreSQL。
- 测试预约清理后正式数据无残留。
- 正式页面完成截图验证，不能只验证 HTTP 状态。
