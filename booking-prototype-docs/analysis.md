# 星海工作室机位预约｜生产化分析 v1.0

更新时间：2026-07-22

## 本轮上线结论

已确认的前端流程保留，但 `localStorage` 只适合演示，不能支持官网多设备预约。生产版改为 Vercel API + PostgreSQL 共享数据库，官网增加正式入口，后台增加密码鉴权。

## 现场模型

- 固定 6 台机器，编号 1–6。
- 两排面对面：第一排为 1、2、3 号，第二排为 4、5、6 号。
- 不虚构门、墙、窗等未确认现场信息，只表达两排相对关系。
- 一次预约锁定：1 个日期 + 1 个时段 + 1 台机器。
- 某台机器可在某个时段被设为可选、已预约或维护；机器是否可选不能只看时段总人数。

## 家长任务

进入页面后按顺序完成：选日期 → 选时段 → 在座位图选机器 → 填姓名、年级、手机号 → 提交。

页面只提供一条简单说明：“先选日期和时段，再选机器。灰色已占用，斜线维护中。”

## 管理员任务

按日期和时段查看同一张座位图；知道 1–6 号机器分别由谁使用；将空闲机器设为维护或恢复；取消预约；临时关闭整个时段。

## 必需状态

- 机器可选、选中、已预约、维护中。
- 时段可用、已满、已关闭。
- 表单未完成、提交中、预约成功、机器刚被占用。
- 后台默认、配置已修改、保存成功、无预约。

## 数据模型

`日期 × 时段 × machineId` 是唯一占位键。机器固定为 `1..6`。预约包含学生姓名、年级、家长手机号、机器编号、状态。维护状态记录在指定日期和时段下，不默认影响其他时段。

数据库使用唯一约束保护有效占位，不能只依赖前端“提交前再检查”。家长查询接口只返回机器状态，不返回姓名或手机号；完整联系方式仅在管理员鉴权后返回。

## 技术与验证

- 正式站保持静态 HTML/CSS/JavaScript，数据通过同域 `/api/booking/*` 和 `/api/admin/*` 访问。
- 数据库采用 Vercel 项目连接的 PostgreSQL；API 端校验日期、时段、机器、手机号与请求体。
- 管理员使用 HttpOnly 会话 Cookie；写操作验证来源并在服务端鉴权。
- 桌面端 1440px、手机端 390px截图；另做跨会话共享、并发冲突、未授权访问和线上域名检查。
- 当前线上官网是本轮参考对象，见 `reference-analysis.md`。

## 风险控制

- 不把管理员密码、数据库地址写入前端或仓库，全部放 Vercel 环境变量。
- 不在家长端返回个人信息；后台会话设置短有效期。
- 数据库和正式页面上线前先走预览部署，验证后才切正式域名。
